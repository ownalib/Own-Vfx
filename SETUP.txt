2. SET UP THE EMAIL PROVIDER
- Open https://resend.com and create/sign into your account.
- For testing with onboarding@resend.dev, the recipient must be the email
  associated with that Resend account. Use ownaleebhattie1@gmail.com for that
  account if you want to test delivery to this website's fixed recipient.
- In Resend open API Keys and create a key with sending access.
- Keep the key private. Do not put it in index.html, GitHub, or chat.
- For production sending, add and verify a domain you own in Resend's Domains
  section, then use a sender address from that verified domain.
- A vercel.app subdomain is not a domain you own for email verification.

3. ADD TWO VERCEL ENVIRONMENT VARIABLES
Vercel > your existing project > Settings > Environment Variables.
Add for Production (and Preview only if you want preview submissions):

Name: RESEND_API_KEY
Value: your private key from Resend

Name: ENQUIRY_FROM_EMAIL
Value for testing: own.vfx <onboarding@resend.dev>
Value for production: own.vfx <an-address@your-verified-domain>

The FROM address is not the visitor's email and should not be your Gmail
address. The visitor's address is set as Reply-To automatically.
The TO address is already fixed in the backend as ownaleebhattie1@gmail.com.

4. DEPLOY
- Framework Preset: Other. Root Directory: your repository root (./).
- Build Command: empty. Output Directory: .
- The provided package.json selects Node.js 22.x for the API function.
- After adding environment variables, go to Deployments, open the latest
  deployment menu and choose Redeploy. Existing deployments do not pick up
  new environment variables until a new deployment is created.
- Wait for Ready and visit your normal production website URL.
